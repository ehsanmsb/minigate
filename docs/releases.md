# Releases

The [Verify workflow](../.github/workflows/verify.yml) checks Go code, the Helm chart and the container build on pull requests. A successful push to `main` runs the same checks, then semantic-release creates a `vX.Y.Z` tag and GitHub release, packages the chart, and publishes `ghcr.io/ehsanmsb/minigate:X.Y.Z` plus `:latest`.

Release versions follow [Conventional Commits](https://www.conventionalcommits.org/): `feat:` increments minor, `fix:` and other recognized types increment patch, and `!` or a `BREAKING CHANGE:` footer increments major. Every successful push to `main` gets at least a patch release, even if its commit title does not follow that format. The first automatic release is `v1.0.0`. Use a Conventional Commit title when squashing a pull request so feature and breaking changes get the right version. Release tags are generated by the workflow.

The chart archive attached to each GitHub release has matching `version` and `appVersion`; its default image tag is that release version. The source chart metadata stays at `1.0.0` because packaging sets the release version without committing generated files.
